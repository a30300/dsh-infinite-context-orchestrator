# Task Auto-Handoff (dsh-infinite-context-orchestrator)

An English overview of the project. For the full documentation see [README.md](README.md) (Chinese) and [USERGUIDE.md](USERGUIDE.md) (Chinese, plain-language walkthrough).

Long agent sessions eventually hit the context limit, and the usual workaround is manual: summarise what happened, open a new session, and re-explain the task from scratch. This plugin does that automatically. When a model's context usage approaches the threshold you configure for that model, the plugin writes a checkpoint of the current state, creates a brand-new top-level session in the same workspace group, and injects a handoff brief into the very first request of the new session, so the new window knows what the task is and where it left off from its first token.

The handoff brief carries the original requirement verbatim alongside the progress summary, the pending todos, the completed work, and the constraints the user stated. Later windows therefore keep sight of the original goal instead of only the recent progress, which is what usually causes a long-running task to drift. Original requirements, checkpoints and briefs can all be inspected on disk under the checkpoint root, and a human-readable copy of the original requirement is written to `requirements/<workspace>.md`.

Everything about thresholds is per model. In the settings page you load the model list from DSH and fill in two numbers for each model you want managed: the model's real prompt budget (that is `n_ctx` minus the reserved output tokens) and its threshold percentage. The percentage is computed against the budget you entered, because local inference servers often give you far less context than the model declaration claims, and a percentage based on the declared window would never fire. Models you did not list are left completely alone, which keeps a 1M-token cloud session from being handed off merely because somebody configured a small local model. If a model has no window configured, the plugin falls back to the window reported by DSH or the provider.

Automatic handoff is opt-in. With it off you get a notice at the threshold and can decide yourself; with it on the plugin performs the whole loop, then cancels the old session's current turn and appends a short "the task has moved to a new session" message at the end of the old conversation, without waking that window up or making it run another turn. Session logs are kept strictly valid: the plugin only writes event types whose format the session schema accepts outside an open turn, and a maintenance script is included to repair old session logs that an earlier version had written incorrectly.

The plugin is a single DSH plugin with no runtime dependencies: the host side handles threshold detection, checkpoint writing, session creation and brief injection, and the client side registers exactly one settings section that follows the DSH interface language for its main controls (Chinese and English are built in, other locales fall back to English). Checkpoints are redacted before they are written, so API keys, tokens, JWTs and home-directory paths do not end up on disk. In practice a handoff costs one short message to the new session and one appended line to the old one; if the model is asked to write the brief itself, it costs one extra model call, which can be turned off by keeping brief generation with the plugin template.

To install, add the package to a DSH profile as a bundle patch either from npm or from a local checkout, then enable it in Settings and fill in the model list. The repository ships the built host bundle and type declarations, so DSH loads it straight from the package directory without a build step. Compatibility is DSH 0.2.1-rc.2 or newer on Node 20 or newer.
